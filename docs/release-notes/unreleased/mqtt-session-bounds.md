## en

- **Devices now have per-device MQTT session bounds.** A device may still connect with its plain client id (`{instance}:{tenant}:{device}`) and with ids that append its own suffix (`{instance}:{tenant}:{device}:{suffix}`), but each device may now use at most 16 distinct suffixed ids. An id the device has used before always connects again, and an id unused for 30 days stops counting. A device may also connect at most 20 times at once, refilling 60 a minute, per device-management replica. A connect over either bound is refused as not authorized, like any other refusal. Firmware that makes up a new client id on every connect, or reconnects with no backoff, is what these refuse. The bounds are `callout.maxSessionsPerDevice`, `callout.connectBurstPerDevice` and `callout.connectsPerMinutePerDevice` in device-management's configuration. Set them only after every device-management pod runs this release, because an older pod refuses a configuration key it does not know. The upgrade creates one new key-value bucket, `dc_mqtt_session_discriminators`. Refusals are counted by `devicechain_devicemanagement_callout_session_limited_total{reason}`. The new alerts are `DeviceMqttSessionLimitSustained` and `DeviceMqttSessionStoreUnavailable`.

## es

- **Los dispositivos tienen ahora límites de sesiones MQTT por dispositivo.** Un dispositivo puede seguir conectándose con su client id simple (`{instance}:{tenant}:{device}`) y con ids que añaden un sufijo propio (`{instance}:{tenant}:{device}:{suffix}`), pero ahora cada dispositivo puede usar como máximo 16 ids distintos con sufijo. Un id que el dispositivo ya usó siempre vuelve a conectarse, y un id sin usar durante 30 días deja de contar. Además, un dispositivo puede conectarse como máximo 20 veces seguidas, con una recarga de 60 por minuto, en cada réplica de device-management. Una conexión que supera cualquiera de los dos límites se rechaza como no autorizada, igual que cualquier otro rechazo. Lo que estos límites rechazan es el firmware que inventa un client id nuevo en cada conexión o que se reconecta sin espera. Los límites son `callout.maxSessionsPerDevice`, `callout.connectBurstPerDevice` y `callout.connectsPerMinutePerDevice` en la configuración de device-management. Configúrelos solo cuando todos los pods de device-management ejecuten esta versión, porque un pod anterior rechaza una clave de configuración que no conoce. La actualización crea un nuevo bucket clave-valor, `dc_mqtt_session_discriminators`. Los rechazos se cuentan en `devicechain_devicemanagement_callout_session_limited_total{reason}`. Las nuevas alertas son `DeviceMqttSessionLimitSustained` y `DeviceMqttSessionStoreUnavailable`.

## zh-CN

- **设备现在有按设备计的 MQTT 会话限制。** 设备仍可使用其基本 client id（`{instance}:{tenant}:{device}`）以及附加自身后缀的 id（`{instance}:{tenant}:{device}:{suffix}`）连接，但现在每台设备最多可使用 16 个不同的带后缀 id。设备用过的 id 总能再次连接，30 天未使用的 id 不再计入。此外，在每个 device-management 副本上，一台设备最多可连续连接 20 次，并以每分钟 60 次的速度恢复。超过任一限制的连接会像其他拒绝一样，以未授权被拒绝。这些限制拒绝的是每次连接都生成新 client id 或不带退避地重连的固件。这些限制是 device-management 配置中的 `callout.maxSessionsPerDevice`、`callout.connectBurstPerDevice` 和 `callout.connectsPerMinutePerDevice`。请在所有 device-management Pod 都运行此版本之后再设置它们，因为旧版 Pod 会拒绝它不认识的配置键。升级会新建一个键值 bucket：`dc_mqtt_session_discriminators`。拒绝次数记录在 `devicechain_devicemanagement_callout_session_limited_total{reason}` 中。新增告警为 `DeviceMqttSessionLimitSustained` 和 `DeviceMqttSessionStoreUnavailable`。
