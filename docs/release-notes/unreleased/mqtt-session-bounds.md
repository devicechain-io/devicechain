## en

- **Devices now have per-device MQTT session bounds.** A device still connects with its plain client id (`{instance}:{tenant}:{device}`) and with ids that append its own suffix (`{instance}:{tenant}:{device}:{suffix}`). No device is refused for the number of ids it uses. Instead, each device holds sessions for at most 16 distinct suffixed ids. When it connects with a new one past that count, the stored session of the id it used least recently is removed from the broker first, and the new id is admitted. The id that was removed can connect again; its first reconnect after the removal may be refused once by the broker, and the device's normal retry then opens a fresh session. A device may also connect at most 20 times at once, refilling 60 a minute, per device-management replica. A connect over that rate is refused as not authorized. The bounds are `callout.maxSessionsPerDevice`, `callout.connectBurstPerDevice` and `callout.connectsPerMinutePerDevice` in device-management's configuration. Set them only after every device-management pod runs this release, because an older pod refuses a configuration key it does not know. Sessions that devices stored before this upgrade are not counted or removed; the broker's own count of stored sessions is `nats_stream_total_messages{stream_name="$MQTT_sess"}`. The upgrade creates one new key-value bucket, `dc_mqtt_session_discriminators`, which holds only keyed digests. Removed sessions are counted by `devicechain_devicemanagement_callout_sessions_evicted_total`, and refusals by `devicechain_devicemanagement_callout_session_limited_total{reason}`. The new alerts are `DeviceMqttConnectRateLimited` and `DeviceMqttSessionStoreUnavailable`.

## es

- **Los dispositivos tienen ahora límites de sesiones MQTT por dispositivo.** Un dispositivo sigue conectándose con su client id simple (`{instance}:{tenant}:{device}`) y con ids que añaden un sufijo propio (`{instance}:{tenant}:{device}:{suffix}`). Ningún dispositivo se rechaza por la cantidad de ids que usa. En su lugar, cada dispositivo mantiene sesiones para como máximo 16 ids distintos con sufijo. Cuando se conecta con uno nuevo por encima de esa cifra, primero se elimina del broker la sesión guardada del id que usó hace más tiempo, y después se admite el id nuevo. El id eliminado puede volver a conectarse; el broker puede rechazar una vez su primera reconexión tras la eliminación, y el reintento normal del dispositivo abre entonces una sesión nueva. Además, un dispositivo puede conectarse como máximo 20 veces seguidas, con una recarga de 60 por minuto, en cada réplica de device-management. Una conexión que supera ese ritmo se rechaza como no autorizada. Los límites son `callout.maxSessionsPerDevice`, `callout.connectBurstPerDevice` y `callout.connectsPerMinutePerDevice` en la configuración de device-management. Configúrelos solo cuando todos los pods de device-management ejecuten esta versión, porque un pod anterior rechaza una clave de configuración que no conoce. Las sesiones que los dispositivos guardaron antes de esta actualización no se cuentan ni se eliminan; el recuento propio del broker de sesiones guardadas es `nats_stream_total_messages{stream_name="$MQTT_sess"}`. La actualización crea un nuevo bucket clave-valor, `dc_mqtt_session_discriminators`, que solo contiene resúmenes con clave. Las sesiones eliminadas se cuentan en `devicechain_devicemanagement_callout_sessions_evicted_total`, y los rechazos en `devicechain_devicemanagement_callout_session_limited_total{reason}`. Las nuevas alertas son `DeviceMqttConnectRateLimited` y `DeviceMqttSessionStoreUnavailable`.

## zh-CN

- **设备现在有按设备计的 MQTT 会话限制。** 设备仍可使用其基本 client id（`{instance}:{tenant}:{device}`）以及附加自身后缀的 id（`{instance}:{tenant}:{device}:{suffix}`）连接。不会因为设备使用的 id 数量而拒绝任何设备。取而代之的是，每台设备最多为 16 个不同的带后缀 id 保留会话。当设备超出该数量、使用新 id 连接时，会先从 broker 中删除它最久未使用的 id 所保存的会话，然后接受新 id。被删除的 id 可以再次连接；删除后它的第一次重连可能会被 broker 拒绝一次，随后设备的正常重试会打开一个新会话。此外，在每个 device-management 副本上，一台设备最多可连续连接 20 次，并以每分钟 60 次的速度恢复。超过该速率的连接会以未授权被拒绝。这些限制是 device-management 配置中的 `callout.maxSessionsPerDevice`、`callout.connectBurstPerDevice` 和 `callout.connectsPerMinutePerDevice`。请在所有 device-management Pod 都运行此版本之后再设置它们，因为旧版 Pod 会拒绝它不认识的配置键。设备在此次升级之前保存的会话不会被计数或删除；broker 自身对已保存会话的计数为 `nats_stream_total_messages{stream_name="$MQTT_sess"}`。升级会新建一个键值 bucket：`dc_mqtt_session_discriminators`，其中只保存带密钥的摘要。被删除的会话记录在 `devicechain_devicemanagement_callout_sessions_evicted_total` 中，拒绝次数记录在 `devicechain_devicemanagement_callout_session_limited_total{reason}` 中。新增告警为 `DeviceMqttConnectRateLimited` 和 `DeviceMqttSessionStoreUnavailable`。
