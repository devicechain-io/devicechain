# Reviewed exceptions for hack/govulncheck.sh.
#
# Format:  <module-dir> <OSV-ID> # why it cannot be fixed, and what would fix it
#
# An entry here is a decision, not a mute button. Three properties keep it honest:
#
#   - it is scoped to ONE module, so it cannot silence the same advisory elsewhere;
#   - the justification is mandatory and the checker rejects a line without one;
#   - it EXPIRES LOUDLY. If the vulnerability stops being reachable, the stale
#     entry fails the build until someone deletes it. An exception nobody has to
#     revisit is `continue-on-error` with extra steps.
#
# Add a line only when there is genuinely no fixed version to move to. If a fix
# exists, take the fix.
#
# ---------------------------------------------------------------------------
# 🔑 IF THE STALENESS CHECK FIRES, SUSPECT THE DATABASE BEFORE THE CODE.
#
# An advisory can be WITHDRAWN, and then a correct entry goes stale with nothing
# in this repository having changed. On 2026-08-18 seven github.com/lib/pq reports
# were published at 16:38Z, reviewed here, and allowlisted — then retracted as
# false positives at 20:22Z, all seven inside 26 seconds. The exceptions went
# stale the same day they were written.
#
# That is the check working, but it presents as a mystery, because vuln.go.dev is
# served by a CDN that propagates a withdrawal UNEVENLY: for a while, different
# edges answer the same request differently, and govulncheck — which exits 0 and
# says nothing about a report it could not resolve — returns a different set of
# findings run to run. Four consecutive local scans produced three different
# answers. During that window NEITHER keeping the entries nor deleting them can
# pass, so there is nothing to fix and nothing to do but wait.
#
# Read the retraction state at the source rather than inferring it from a run:
#
#   curl -s https://raw.githubusercontent.com/golang/vulndb/master/data/osv/<ID>.json | jq .withdrawn
#
# A non-null `withdrawn` means the report is gone and the entry should go with it.
# If repeated scans disagree with each other, the DB is still propagating — wait
# for it, rather than rewriting this file to match whichever variant the last run
# happened to fetch.
# ---------------------------------------------------------------------------
