## en

- **Device bulk changes are available as Preview.** A bulk change sets or removes one declared SHARED configuration key (`config.set`) on up to 10,000 devices: plan it, create it, review its contract, start it, and follow each device's line until the device itself answers for it. The device-management GraphQL API serves `planBulkChange`, `createBulkChange`, `startBulkChange`, `pauseBulkChange`, `resumeBulkChange`, `abortBulkChange`, `reverseBulkChange`, `resolveAmbiguousBulkChangeLines`, `previewBulkChangeResume`, `previewBulkChangeReversal`, `bulkChange`, `bulkChanges` and `bulkChangeLines`, and `dcctl bulk-change` adds `plan`, `create`, `start`, `status`, `lines`, `pause`, `resume`, `abort`, `reverse` and `resolve`. A line counts as confirmed only on the device's own report; a line no report decides by its deadline ends ambiguous, and a person can record a verdict on it with a recent second factor. Creating, starting, resuming, reversing and resolving need the `fleet:operate` authority, which no built-in role grants (a role with every authority, `*`, holds it; otherwise grant it in a custom role); pausing and aborting need only `device:write`. A start or resume is refused with `BULK_CHANGES_NOT_ACTIVATED` while orphaned device attribute rows remain, and with `ACTIVATION_CHECK_UNAVAILABLE`, which can be retried, when the check for them could not be completed. Agent and service identities and scoped members are refused. All of it is Preview and may change in a minor release. See [Device bulk changes](../guides/bulk-changes.md).
- **Alerts and metrics for bulk changes.** With `metrics.alerts` on, the chart adds a `bulk-changes` PrometheusRule with seven alerts — `BulkChangesNotAdvancing`, `BulkChangesStalled`, `BulkChangesDriverSilent`, `BulkChangesAuthorityUnavailable`, `BulkChangesSettlementLagging`, `BulkChangesFencePending` and `BulkChangesNotActivated` — each with an entry in the alert runbook. They read the `devicechain_devicemanagement_bulk_change_*` series, which carry no tenant, operation or device label. A device-management pod still on v1.9 does not export those series, so while device-management rolls the alerts read only the upgraded pods; nothing to do. `BulkChangesSettlementLagging` also reads the `devicechain_devicemanagement_bulk_change_reconciler_lag_seconds` gauge, which each pod measures once a minute and which is `NaN` while a pod has no successful measurement of its own, and the alert fires when no pod can measure it.

## es

- **Los cambios masivos en dispositivos están disponibles como Preview.** Un cambio masivo establece o elimina una clave de configuración declarada con ámbito SHARED (`config.set`) en hasta 10.000 dispositivos: se planifica, se crea, se revisa su contrato, se inicia y se sigue la línea de cada dispositivo hasta que el propio dispositivo responde por ella. La API GraphQL de device-management sirve `planBulkChange`, `createBulkChange`, `startBulkChange`, `pauseBulkChange`, `resumeBulkChange`, `abortBulkChange`, `reverseBulkChange`, `resolveAmbiguousBulkChangeLines`, `previewBulkChangeResume`, `previewBulkChangeReversal`, `bulkChange`, `bulkChanges` y `bulkChangeLines`, y `dcctl bulk-change` añade `plan`, `create`, `start`, `status`, `lines`, `pause`, `resume`, `abort`, `reverse` y `resolve`. Una línea solo cuenta como confirmada con el informe del propio dispositivo; una línea que ningún informe decide antes de su plazo termina ambigua, y una persona puede registrar un veredicto sobre ella con un segundo factor reciente. Crear, iniciar, reanudar, revertir y resolver requieren el permiso `fleet:operate`, que ningún rol integrado concede (un rol con todos los permisos, `*`, lo tiene; en otro caso concédelo en un rol personalizado); pausar y abortar solo requieren `device:write`. Un inicio o una reanudación se rechaza con `BULK_CHANGES_NOT_ACTIVATED` mientras queden filas huérfanas de atributos de dispositivo, y con `ACTIVATION_CHECK_UNAVAILABLE`, que puede reintentarse, cuando no se pudo completar la comprobación de esas filas. Se rechazan las identidades de agente y de servicio y los miembros con ámbito limitado. Todo ello es Preview y puede cambiar en una versión menor. Consulta [Cambios masivos en dispositivos](../guides/bulk-changes.md).
- **Alertas y métricas para los cambios masivos.** Con `metrics.alerts` activado, el chart añade una PrometheusRule `bulk-changes` con siete alertas —`BulkChangesNotAdvancing`, `BulkChangesStalled`, `BulkChangesDriverSilent`, `BulkChangesAuthorityUnavailable`, `BulkChangesSettlementLagging`, `BulkChangesFencePending` y `BulkChangesNotActivated`—, cada una con su entrada en el runbook de alertas. Leen las series `devicechain_devicemanagement_bulk_change_*`, que no llevan etiqueta de tenant, de operación ni de dispositivo. Un pod de device-management que sigue en v1.9 no exporta esas series, así que mientras device-management se actualiza las alertas solo leen los pods ya actualizados; no hay nada que hacer. `BulkChangesSettlementLagging` también lee el indicador `devicechain_devicemanagement_bulk_change_reconciler_lag_seconds`, que cada pod mide una vez por minuto y que vale `NaN` mientras un pod no tiene ninguna medición correcta propia, y la alerta salta cuando ningún pod puede medirlo.

## zh-CN

- **设备批量变更以 Preview 形式提供。** 一次批量变更在最多 10,000 台设备上设置或移除一个已声明的 SHARED 配置键（`config.set`）：先规划、再创建、审阅其契约、启动，然后跟踪每台设备的行，直到设备本身对其作出回应。device-management GraphQL API 提供 `planBulkChange`、`createBulkChange`、`startBulkChange`、`pauseBulkChange`、`resumeBulkChange`、`abortBulkChange`、`reverseBulkChange`、`resolveAmbiguousBulkChangeLines`、`previewBulkChangeResume`、`previewBulkChangeReversal`、`bulkChange`、`bulkChanges` 和 `bulkChangeLines`，`dcctl bulk-change` 新增 `plan`、`create`、`start`、`status`、`lines`、`pause`、`resume`、`abort`、`reverse` 和 `resolve`。只有设备自己的报告才能使一行被确认；截止时间前没有报告作出判定的行会成为不明确状态，用户可在近期完成第二因素验证后为其记录裁定。创建、启动、恢复、撤销和裁定需要 `fleet:operate` 权限，任何内置角色都不授予该权限（拥有全部权限 `*` 的角色具备该权限；否则请在自定义角色中授予）；暂停和中止只需 `device:write`。仍有孤立的设备属性行时，启动或恢复会以 `BULK_CHANGES_NOT_ACTIVATED` 被拒绝；无法完成对这些行的检查时，会以可重试的 `ACTIVATION_CHECK_UNAVAILABLE` 被拒绝。代理和服务身份以及具有受限范围的成员会被拒绝。以上全部为 Preview，可能在次版本中变更。参见[设备批量变更](../guides/bulk-changes.md)。
- **批量变更的告警和指标。** 启用 `metrics.alerts` 时，chart 会新增一个 `bulk-changes` PrometheusRule，包含七条告警——`BulkChangesNotAdvancing`、`BulkChangesStalled`、`BulkChangesDriverSilent`、`BulkChangesAuthorityUnavailable`、`BulkChangesSettlementLagging`、`BulkChangesFencePending` 和 `BulkChangesNotActivated`——每条在告警运行手册中都有对应条目。这些告警读取 `devicechain_devicemanagement_bulk_change_*` 序列，这些序列不带租户、操作或设备标签。仍在 v1.9 上的 device-management Pod 不导出这些序列，因此在 device-management 滚动升级期间，这些告警只读取已升级的 Pod；无需任何操作。 `BulkChangesSettlementLagging` 还会读取 `devicechain_devicemanagement_bulk_change_reconciler_lag_seconds` 指标；每个 Pod 每分钟测量一次，Pod 自身没有成功测量时该指标为 `NaN`，当没有任何 Pod 能够测量时，该告警会触发。
