## en

- **`dcctl install --output json`.** `dcctl install` takes a new `-o, --output` flag. `--output json` reports the install as an event stream for automation: one JSON object per line on stdout and nothing else there, covering each stage as it starts, progresses, finishes or fails, the preflight report, the install's own output as log lines, and a final summary line with the verdict. The stream never reads stdin: `--yes` gives the one confirmation an install asks, and without it a run that needs that confirmation is refused before it changes anything. Secret values are never written to it. The exit status and the failure message on stderr are unchanged. The default, `--output text`, prints exactly what it printed before. The events are described in the [install event stream reference](../reference/install-events.md).
- **`dcctl install --output json` keeps its guarantees at the edges.** The exit status always matches the stream's final verdict, `0` or `1`, even when a tool the install ran was killed or dcctl itself failed unexpectedly, and the stream still ends with its summary line in that case; text output also exits only `0` or `1` again. `--help` with `--output json` prints the help on stderr and leaves stdout empty. Nothing the install runs can read stdin, so a kubeconfig exec credential plugin runs non-interactively. A kubeconfig dcctl cannot parse is now reported by its path, without the parser's reason, which could quote the tokens and passwords in the file, in both output formats, and the kubeconfig's credentials are also redacted from the stream's log lines. With `--output json`, the error printed on stderr and everything else that reaches dcctl's own stdout and stderr during the run, a kubeconfig exec credential plugin's stderr included, are redacted too; with `--output text`, the error dcctl prints is. A kubeconfig that cannot be read or turned into a client is reported by the kind of problem, the file and the context name. A kubeconfig credential is redacted only as a whole word and never changes what the run does, and a value too short to redact (under 4 bytes) is warned about rather than silently left. The [install event stream reference](../reference/install-events.md) now lists every field of every event and describes how progress is coalesced and when an interrupted OpenTofu command can outlive the run.
- **Bounded JSON-mode shutdown.** `dcctl install --output json` no longer hangs while draining process output when the original stderr consumer stops reading. Diagnostics received by the reader are preserved through the drain deadline; pending diagnostics may be dropped after that deadline.

## es

- **`dcctl install --output json`.** `dcctl install` admite un nuevo indicador `-o, --output`. `--output json` informa de la instalación como un flujo de eventos para la automatización: un objeto JSON por línea en stdout y nada más allí, que cubre cada etapa cuando empieza, avanza, termina o falla, el informe de comprobaciones previas, la salida de la propia instalación como líneas de registro y una línea final de resumen con el veredicto. El flujo nunca lee stdin: `--yes` da la única confirmación que pide una instalación y, sin él, una ejecución que necesita esa confirmación se rechaza antes de cambiar nada. Nunca se escriben valores secretos en él. El código de salida y el mensaje de error en stderr no cambian. El valor predeterminado, `--output text`, imprime exactamente lo mismo que antes. Los eventos se describen en la [referencia del flujo de eventos de la instalación](../reference/install-events.md).
- **`dcctl install --output json` mantiene sus garantías en los casos límite.** El código de salida siempre coincide con el veredicto final del flujo, `0` o `1`, incluso cuando se mató una herramienta que ejecutó la instalación o el propio dcctl falló de forma inesperada, y en ese caso el flujo también termina con su línea de resumen; la salida de texto vuelve a salir solo con `0` o `1`. `--help` con `--output json` imprime la ayuda en stderr y deja stdout vacío. Nada de lo que ejecuta la instalación puede leer stdin, así que un plugin de credenciales exec del kubeconfig se ejecuta de forma no interactiva. Un kubeconfig que dcctl no puede analizar se informa ahora por su ruta, sin el motivo del analizador, que podía citar los tokens y contraseñas del archivo, en ambos formatos de salida, y las credenciales del kubeconfig también se eliminan de las líneas de registro del flujo. Con `--output json`, el error que se imprime en stderr y todo lo demás que llega a la stdout y la stderr de dcctl durante la ejecución, incluida la stderr de un plugin de credenciales exec del kubeconfig, también se redactan; con `--output text`, se redacta el error que imprime dcctl. Un kubeconfig que no puede leerse o con el que no puede crearse un cliente se informa por el tipo de problema, el archivo y el nombre del contexto. Una credencial del kubeconfig se redacta solo como palabra completa y nunca cambia lo que hace la ejecución, y un valor demasiado corto para redactarse (menos de 4 bytes) se advierte en lugar de dejarse sin más. La [referencia del flujo de eventos de la instalación](../reference/install-events.md) enumera ahora todos los campos de cada evento y describe cómo se agrupa el progreso y cuándo una orden de OpenTofu interrumpida puede sobrevivir a la ejecución.
- **Cierre acotado en modo JSON.** `dcctl install --output json` ya no se bloquea al vaciar la salida del proceso cuando el consumidor original de stderr deja de leer. Los diagnósticos recibidos por el lector se conservan hasta el límite de tiempo de vaciado; los diagnósticos pendientes pueden descartarse después de ese límite.

## zh-CN

- **`dcctl install --output json`。** `dcctl install` 新增 `-o, --output` 标志。`--output json` 以面向自动化的事件流报告安装过程：在 stdout 上每行一个 JSON 对象，且 stdout 上没有其他内容；内容涵盖每个阶段的开始、进展、完成或失败，预检报告，以日志行形式呈现的安装自身输出，以及带有结论的最后一行总结。事件流从不读取 stdin：`--yes` 提供安装唯一会提出的确认；没有它时，需要该确认的运行会在做出任何改动之前被拒绝。机密值从不写入事件流。退出状态和 stderr 上的失败信息保持不变。默认的 `--output text` 打印的内容与以前完全相同。事件说明见[安装事件流参考](../reference/install-events.md)。
- **`dcctl install --output json` 在边界情况下也保持其保证。** 退出状态始终与事件流的最终结论一致，为 `0` 或 `1`，即使安装所运行的工具被杀死或 dcctl 自身意外失败也是如此，此时事件流同样以总结行结束；文本输出也重新只以 `0` 或 `1` 退出。`--help` 与 `--output json` 一起使用时，帮助打印在 stderr 上，stdout 保持为空。安装所运行的任何东西都无法读取 stdin，因此 kubeconfig 的 exec 凭据插件以非交互方式运行。dcctl 无法解析的 kubeconfig 现在只按其路径报告，不再附带解析器给出的原因（该原因可能引用文件中的令牌和密码），两种输出格式都是如此；kubeconfig 中的凭据也会从事件流的日志行中移除。使用 `--output json` 时，打印在 stderr 上的错误以及运行期间到达 dcctl 自身 stdout 和 stderr 的其他所有内容（包括 kubeconfig 的 exec 凭据插件的 stderr）也会被替换；使用 `--output text` 时，dcctl 打印的错误会被替换。无法读取或无法构建客户端的 kubeconfig 按问题类型、文件和上下文名称报告。kubeconfig 中的凭据只作为完整单词被替换，绝不会改变运行的行为；过短而无法替换的值（不足 4 字节）会给出警告，而不是被默默放过。[安装事件流参考](../reference/install-events.md)现在列出每个事件的全部字段，并说明进度如何合并，以及被中断的 OpenTofu 命令何时可能比运行存在得更久。
- **JSON 模式可在限定时间内结束。** 当原始 stderr 的使用方停止读取时，`dcctl install --output json` 不再因排空进程输出而挂起。读取器已收到的诊断信息会保留至排空期限；超过期限后，尚未输出的诊断信息可能被丢弃。
