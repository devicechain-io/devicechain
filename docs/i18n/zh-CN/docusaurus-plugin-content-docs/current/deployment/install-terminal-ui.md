# 安装终端界面 {#install-terminal-ui}

`dcctl install local --ui=tui` 在全屏终端界面中运行集群安装。它会显示安装将要做什么，在屏幕上运行只读的预检，让您更改集群选项，并在安装任何内容之前请您批准确切的计划。随后它会显示正在运行的各个安装阶段，最后显示结果以及接下来要运行的命令。

```bash
dcctl install local --ui=tui
dcctl install local --ui=tui --kube-context prod
```

在此版本中，终端界面是**可选的**：不加 `--ui` 时，无论是否在终端中运行，`dcctl install` 的输出、提示和退出方式都与以往完全相同。两种方式安装的内容相同，使用相同的参数、相同的检查和相同的退出状态；安装具体做什么，请参见[安装集群](./bootstrap.md#install)。它只涵盖集群安装。`dcctl bootstrap` 保持不变，仍以纯文本方式运行。

## 何时使用终端界面 {#when-used}

`--ui` 接受以下三个值之一：

| 值 | 效果 |
| --- | --- |
| `plain`（默认） | `dcctl install` 一直以来输出的文本。 |
| `tui` | 当 stdin、stdout 和 stderr 都是交互式终端时使用终端界面，否则使用纯文本输出，保持不变。 |
| `auto` | 在交互式终端上使用终端界面，在其他所有情况下（包括使用 `--yes` 或 `--dev` 时）使用纯文本输出。 |

即使使用 `--ui=tui`，在以下情况下也会得到纯文本输出，不含转义序列，也不会出现新的提示：

- stdin、stdout 或 stderr 被重定向到文件或管道；
- 设置了 `CI` 环境变量；
- `TERM` 为空或为 `dumb`（在 Linux 和 macOS 上）；
- Windows 控制台无法处理虚拟终端序列（旧版控制台主机）；
- 传入了 `--dry-run`，它始终输出原有的演练输出。

使用 `--ui=tui --yes` 或 `--ui=tui --dev` 时，终端界面**只显示进度**：没有用于选择或审核的屏幕，不会等待您操作，安装结束后自动退出。

`--ui=tui` 不能与 `--output json` 同时使用；这种组合会在任何操作开始之前被拒绝。

## 哪些操作会开始安装，哪些不会 {#what-starts-an-install}

在审核屏幕上选择 **Approve and install** 之前，不会安装任何内容。在此之前，终端界面只进行读取：欢迎屏幕显示计划，预检与纯文本安装运行的只读检查完全相同。

在批准之前离开不会更改任何内容。在此之前选择 Exit、按 Ctrl+C、收到中断信号或终端界面停止，命令都会结束且不做任何更改，退出状态为 1。如果安装开始之后终端界面停止工作，同一次安装会以纯文本输出继续进行；安装绝不会被启动第二次。

批准审核即是对计划所需一切的回答。特别是，如果本地 kind 集群尚不存在，批准同时会回答是否创建它的问题，且仅针对该集群和该计划。返回并更改任何内容都会生成新的计划，新计划需要重新运行检查并单独审核。

## 各个屏幕 {#screens}

### 启动画面 {#splash}

显示 DeviceChain 徽标和 dcctl 版本。它不执行任何操作。在支持的本地终端上，它会显示最长 1.2 秒的动画；其他情况下显示静态徽标或一行标题。按任意键即可跳过，且该按键不会传递到下一个屏幕。在启动画面上按 Ctrl+C 会退出。传入 `--no-splash` 可不显示启动画面。通过 SSH 时它从不显示动画，使用 `--yes`、`--dev`、`--dry-run` 或 `--help` 时从不显示。

### 欢迎 {#welcome}

显示命令的范围（"This installs shared cluster prerequisites. Create an instance later with dcctl bootstrap."）、命令行解析出的目标、规模、拓扑和镜像来源，以及 "No changes have been made." 字样。Continue 会运行预检。

### 预检 {#preflight}

只读检查会在运行时逐项显示。每项检查都以文字显示：`PASS`、`WARN`、`FAIL`、`UNKNOWN`、`NOT NEEDED`、`NOT CHECKED` 或 `INFO`。用方向键移动到某项检查即可查看其修复方法。

- **Recheck** 在您修复问题后重新运行检查。
- **Switch to Compact**（或切换回 Standard）会说明这一更改意味着什么，然后针对新规模重新运行所有检查。
- **Choose another context** 从 kubeconfig 中的名称里选择一个现有集群。
- 只要有任何检查失败，**Continue 就不可用**，屏幕上也没有绕过的办法。命令行上的 `--skip-preflight` 仍然是跳过检查的唯一方式。

#### 现有集群检查 {#preflight-advisory}

使用 `--kube-context` 时，检查之后会出现一组 "Existing cluster (advisory)"。它向集群提出只读问题：API 服务器的名称能否解析，它是否以该上下文信任的 TLS 证书应答，该上下文的凭据是否被接受，以及这些凭据能否创建安装所创建的资源。它还会检查本机能否访问此计划下载所用的提供程序、chart 和镜像仓库。这些检查只是建议：发现的问题显示为 `WARN`，无法判断的显示为 `UNKNOWN` 或 `NOT CHECKED`，并且从不阻止 Continue。

- **凭据插件。** 通过 exec 插件获取凭据的上下文（GKE、EKS 和 AKS 的上下文通常如此）会像 kubectl 那样运行该插件来进行身份验证：从不以交互方式运行，没有终端，输入为空，最长 10 秒；时间用完或您离开该屏幕时，插件及其启动的所有进程都会被一并停止。插件输出的凭据只会发送给该上下文的 API 服务器，并且从不显示。必须以交互方式运行的插件（`interactiveMode: Always`）不会运行，显示为 `NOT CHECKED`；未安装的插件显示为 `WARN`；运行失败、挂起或没有输出可用凭据的插件显示为 `UNKNOWN`。插件输出的错误信息从不显示，因为其中可能包含令牌或密钥：该行只说明插件是如何失败的，针对该上下文运行 `kubectl auth whoami` 可以看到插件自己的信息。旧式的 `auth-provider` 条目从不运行。
- **仓库。** 只检查此计划所安装组件的 chart 仓库，因此 Compact（不包含监控）以及 Advanced 面板中的监控和 CloudNativePG 选项都会改变检查列表。Ingress 控制器的 chart 跟随集群而定：始终检查 Traefik 的，当集群已在运行 ingress-nginx 时（除非指定 `--remove-legacy-ingress`，安装会保留它）也检查 ingress-nginx 的，依据是集群的 IngressClass。
- **代理。** 这些检查从不经过代理。当上下文或环境（`HTTPS_PROXY` 等）中配置了代理时，需要经过该代理的行显示为 `NOT CHECKED`。

### 集群选项 {#cluster-choices}

目标（可重命名的托管本地 kind 集群，或现有上下文）、规模（Standard 或 Compact）以及拓扑（Single 或 HA）。在命令行上设置的值会标明是由哪个参数设置的。Compact 会省略的内容会在其下方说明。

**Advanced** 会打开一个面板，其中可编辑监控组件、内置的 CloudNativePG operator，以及在 Compact 下的 TLS。它会按计划的实际结果显示是否进行数据库备份。命令行中给出的其他所有参数都会按名称列在其中，并原样带入安装。凭据只显示为 "configured (hidden)"。

每项更改都按命令行的方式进行校验，因此命令行会拒绝的组合在屏幕上同样会被拒绝，并且会针对更改后的计划重新运行只读检查。

### 审核 {#review}

按命令行的解析方式展示计划：目标及其是新建还是复用、版本和镜像仓库、规模和拓扑、TLS、监控、备份、各项警告，以及集群状态的保存位置。页面还会显示**等效命令**：使用 `--yes`、可重现此计划的非交互式 `dcctl install` 命令。告警 webhook 等凭据在其中只以占位符显示，此时该命令会被标记为模板。

审核页面打开时焦点位于 **Back**，页面稳定之前按下的键会被忽略，因此多按一次 Enter 永远不会批准它。

### 进度 {#progress}

显示各个安装阶段，每个阶段都有一个状态词（`DONE`、`RUN`、`WAIT`、`FAIL`、`STOP`）和自己的进度条。只有存在可实际计数的内容（例如 OpenTofu 操作或已就绪的副本 `2/3`）时，进度条才表示实际度量；否则会用一个标记表示工作正在进行。总进度条统计的是适用阶段中已完成的阶段数。它从不表示安装的百分比，也从不估计剩余时间，剩余时间始终显示为 `Remaining: unknown`。如果一段时间内没有观察到新的进展，屏幕会说明工作仍在进行，而不会称其为卡住。最后一个阶段之后会显示 `Finalizing`，直到安装报告其结果。

按 `l` 打开日志面板，其中显示已去除凭据的安装输出。PgUp 和 PgDn 用于滚动并暂停日志；`f` 或 End 会重新跟随日志。

**安装过程中按 Ctrl+C** 会安全地停止安装：屏幕会显示 "Interrupt received. Waiting for the operation to stop safely. Nothing is being rolled back."，并一直保留到安装停止。第二次按 Ctrl+C 会立即退出而不再等待，与纯文本安装相同。Esc 从不会停止安装。

### 结果 {#result}

- **成功**显示 "Shared prerequisites installed"，并列出集群、其规模、TLS、监控、备份和连接预算。集群没有自己的控制台，因此不会显示控制台。下一步是在该集群上创建实例的 `dcctl bootstrap` 命令。Done 以 0 退出。
- **失败**会指出失败的阶段及其原因、可能已更改的内容、集群锁是否已释放、用于检查集群的命令以及修复方法。安装是收敛的，因此修复方法是纠正原因后**再次运行同一命令**；屏幕会显示用于重新运行的命令。**Review for re-run** 会在失败的运行完全停止后，将同一请求重新带回审核。不会回滚任何内容，关闭失败屏幕也绝不会把结果变为成功：dcctl 以 1 退出。
- 如果安装**已记录但在就绪等待超时时副本仍在加入**，会显示为说明这一情况的失败，绝不会显示为成功。

dcctl 退出时会恢复终端并输出一段简短摘要：结果、目标和下一条命令。其中不包含任何凭据。

## 按键 {#keys}

| 按键 | 安装之前 | 安装期间及之后 |
| --- | --- | --- |
| Tab / Shift+Tab | 在字段和操作之间移动 | 在结果屏幕的操作之间移动 |
| ↑ / ↓ | 选择选项，或在检查之间移动 | — |
| Space | 切换选项 | — |
| Enter | 执行选中的操作 | 在结果屏幕上执行选中的操作 |
| `y` / `n` | — | 回答安装在屏幕上提出的问题（只显示进度的运行） |
| Esc | 返回上一个屏幕（保留您的更改） | 关闭帮助。从不会停止安装 |
| `?` / F1 | — | 帮助，在结果屏幕上 |
| `l`、PgUp / PgDn、`f` / End | — | 打开日志面板、滚动、跟随 |
| `q` | 移动到 Exit | 安装结束后退出 |
| Ctrl+C | 退出；不做任何更改 | 安全地停止安装；再按一次立即退出 |

每个屏幕的底部都会列出在该屏幕上可用的按键。鼠标报告处于关闭状态，因此用鼠标选择和复制文本的方式与在任何终端中相同。选中的控件用 `›` 标记并反色显示，从不只靠颜色区分。

## 终端与无障碍 {#accessibility}

终端界面会根据终端的能力进行调整。每种状态都以文字显示，因此不依赖颜色：

| 终端 | 显示效果 |
| --- | --- |
| 真彩色，Unicode | 全彩色、DeviceChain 徽标、用色块绘制的进度条 |
| 256 色，Unicode | 同上，使用最接近的 256 色调色板 |
| 16 色，或无法确定是否支持 Unicode | ASCII 边框和进度条，用文字标题代替徽标，静态的 `working` 标记 |
| 设置了 `NO_COLOR` | 完全没有颜色，用文字标题代替徽标；由文字表示每种状态，没有任何动画 |

`NO_COLOR` 优先于 `CLICOLOR_FORCE`。通过 SSH 时启动画面为静态。布局会随终端尺寸变化：100×30 及以上为完整布局，80 列及以上为单列布局，60 列及以上为不带外边框的紧凑布局。终端小于 60×16 时，安装之前的屏幕会请您放大窗口或使用 `--ui=plain`；安装期间则显示一个最简状态块。调整窗口大小从不会取消或重新开始任何操作。

**使用屏幕阅读器时，请使用 `--ui=plain`。** 终端界面会重绘整个屏幕，屏幕阅读器难以跟随，它也不是为屏幕阅读器设计的。`--ui=plain`（默认值）以普通文本行和提示的形式执行相同的安装，并且会一直保留：无论以后默认值如何变化，它都可以使用。

在 Windows 上，终端界面需要能处理虚拟终端序列的控制台：Windows Terminal，或当前 Windows 10 和 11 的控制台主机，配合 PowerShell 或 `cmd` 使用。它不需要 Bash、WSL 或其他工具。在旧版控制台上，它会回退到纯文本输出。每次退出时（包括按 Ctrl+C 和出错时），控制台的模式都会恢复原样。

## 退出状态 {#exit-status}

退出状态与纯文本安装相同：安装成功时为 0，安装失败、被拒绝或被停止时为 1。离开某个屏幕从不会改变退出状态。

## 先集群，后实例：`dcctl setup local`（Preview） {#setup-local}

`dcctl setup local` 在一次引导式会话中先安装集群，再为第一个实例执行 bootstrap。它处于 Preview 阶段。`dcctl install` 和 `dcctl bootstrap` 不受影响，仍是以脚本方式执行各个步骤的方式。

它分为两个阶段，每个阶段都有自己的审核和自己的批准：

1. **集群。** 与 `dcctl install local --ui=tui` 相同的屏幕，从欢迎屏幕到审核屏幕。**批准并安装**会安装集群。完成后按 Enter 继续。
2. **实例。** 交接屏幕说明集群已安装，并显示以后创建实例所用的 `dcctl bootstrap` 命令。**继续创建实例**进入实例和根密钥托管的选项，然后进入实例自己的审核屏幕。**批准并创建实例**开始 bootstrap。运行到托管步骤时会在屏幕上询问托管口令，口令从不显示。运行成功后依次显示托管回执、一次性的首次登录密码和实例摘要。

实例的任何部分都不会在没有其自身批准的情况下运行，集群的批准也不会回答实例运行提出的任何问题。每个会继续往下走的屏幕（交接屏幕和两个审核屏幕）在显示片刻之前不接受按键，因此提前输入的按键无法批准任何操作。

`dcctl setup local` 只能以引导方式使用。它要求 stdin、stdout 和 stderr 都是交互式终端（不是 CI，也不是 `TERM=dumb`），并且没有 `--yes`。没有终端时它不做任何更改，以 2 退出，并给出应改为运行的两个命令。它的标志（`--kube-context`、`--cluster`、`--compact`、`--ha`、`--no-splash`）只决定屏幕的起始值，每一项都可以在屏幕上更改。

如果在集群阶段之后退出或实例创建失败，集群仍保持已安装状态。setup 会说明这一点，并打印创建该实例的确切 `dcctl bootstrap` 命令：如果已经做出选择，则包含你所做的选择。

| 退出状态 | 含义 |
| --- | --- |
| 0 | 集群已安装，实例已创建 |
| 1 | 集群阶段失败，或在批准后被停止，与 `dcctl install` 以 1 退出相同 |
| 2 | 未做任何更改：在集群批准之前停止，或在开始之前被拒绝 |
| 3 | 集群已安装；未创建实例（在实例批准之前退出） |
| 4 | 集群已安装；创建实例失败，或在批准后被停止 |
