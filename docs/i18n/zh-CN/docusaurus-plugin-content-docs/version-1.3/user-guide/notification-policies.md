# 通知策略 {#notification-policies}

**通知策略**决定一条已触发的告警要通知谁、通过哪个渠道，以及何时通知。本章介绍如何在控制台中查看通知策略，以及如何为策略设置**静默时段**，使其在夜间不再打扰人员，并在静默时段结束时发出此前暂存的通知。本章面向负责值班路由的管理员。静默时段的行为，以及如何通过 API 设置，请参阅[静默时段](/guides/notification-channels#quiet-hours)。

通知策略位于侧边栏的 **Monitor → Notification Policies**（通知策略）。如果你的角色可以读取通知，就会看到这一项。修改策略还需要写入通知的权限；没有该权限时，策略以只读方式打开。

## 策略列表 {#the-policy-list}

列表显示每条策略的令牌、名称、是否启用、路由规则数量，以及静默时段。**Quiet hours**（静默时段）列显示该策略静默时段所用的时区；没有静默时段时显示短横线。点击某一行即可打开该策略。

## 创建和编辑策略 {#creating-and-editing-a-policy}

点击 **New notification policy**（新建通知策略）。表单需要填写：

- **Token**（令牌）：策略的标识符。创建后不能更改。
- **Name**（名称）和 **Description**（描述）。
- **Enabled**（启用）：已停用的策略不会发送任何内容，并会丢弃它为静默时段暂存的通知。
- **Throttle (seconds)**（节流，秒）：针对同一告警的两次通知之间的最短间隔。留空表示不节流。
- **Escalate after (seconds)**（升级等待，秒）和 **Max escalations**（最大升级次数）：未确认的告警等待多久会被再次通知，以及最多通知几次。参阅[节流与升级](/guides/notification-channels#throttling-and-escalation)。
- **Quiet hours**（静默时段），见下文。

控制台不编辑**路由规则**。在这里创建的策略一开始没有任何规则；打开一条策略时，会以只读方式显示它的规则：每个严重程度、所用渠道及其接收人。保存时绝不会改动这些规则。请按[配置通知渠道](/guides/notification-channels#policies)中的说明，通过 API 添加或修改规则。

编辑策略时，**Save changes**（保存更改）只发送你改动过的字段。控制台还会告诉服务器你查看的是策略的哪个版本。如果期间有其他人保存了该策略，你的保存会被拒绝，并提示策略已被其他写入者修改；请刷新页面后重新进行修改。

## 静默时段 {#quiet-hours}

勾选 **Hold notifications during quiet hours**（在静默时段内暂存通知）即可为策略设置静默时段。策略处于静默时段内时会暂存通知，并在静默时段结束时发出，除非告警在此期间已被确认或清除。取消勾选并保存即可移除静默时段。

开启静默时段后，表单会显示：

- **Time zone**（时区）：解释时段所用的时区。默认为浏览器所在的时区。时段时间是该时区的挂钟时间，因此静默时段会随该时区一起遵循夏令时。
- **Quiet slots**（静默时段列表）：每个时段一行，包括星期几、开始时间和以分钟计的时长。使用 **Add slot**（添加时段）可以添加更多，最多 56 个。时段可以跨越午夜，周日的时段会延续到周一。
- **Bypass severity**（放行严重程度）：严重程度达到或高于该值的告警，即使在静默时段内也会立即发送。首次开启静默时段时，默认为 **Critical**。选择 **None** 则暂存所有严重程度。

时段之间不能重叠，合计也不能覆盖整周。表单会在你输入时指出这两种情况，并在修正之前保持 **Save changes** 不可用；若要让策略完全静默，请改为停用该策略。最终由服务器在保存时校验。

如果策略的静默时段是控制台无法读取的格式，控制台会如实说明，而不会显示成一份空的时间表。静默时段仍原样保存并继续生效，保存其他更改时也不会改动它们。

静默时段不是[维护窗口](/guides/maintenance-windows)。维护窗口属于设备类型，用于暂存破坏性命令；静默时段属于通知策略，用于暂存该策略的通知。
