# Intended breaking changes to the served GraphQL schemas, against the baseline release.
#
# Checked by `go run ./cmd/sdlcompat` (from backend/tools/docsgql), which the `api-compat`
# CI job runs through hack/check-graphql-compat.sh. A breaking change that is not listed
# here fails the pull request; the failure prints the exact line to add. One line per change:
#
#   <baseline-tag> <schema> <coordinate> <kind> <reason>
#
#   baseline-tag  the release the change breaks against, as the failure names it (vX.Y.Z)
#   schema        the published schema name: <area>, <area>-admin or <area>-settings
#   coordinate    Type, Type.field, Type.field(arg:), Enum.VALUE, Input.field, @directive
#   kind          the breaking kind the failure names (field-removed, argument-type-changed, ...)
#   reason        why, and what a client uses instead. Required.
#
# A line applies only while its baseline-tag IS the baseline. When the next release is
# tagged, the baseline moves past it and the check reports it as expired: delete it then.
# A line for the current baseline that matches no change fails, so remove a declaration
# when you revert the change it excused.
#
# Before v1.0.0 a declared break may ship in any release; say so in that release's
# highlights (.github/release-highlights.json, `"breaking": true`). From v1.0.0 a covered
# interface breaks only in a major release.
v0.25.2 device-management Mutation.createProvisioningProfile field-type-changed the server now generates the provision secret and returns it once beside the profile, so the result is ProvisioningProfileSecretResult { profile, issuedSecret }; select the profile fields under `profile` and read the secret from `issuedSecret`
v0.25.2 device-management ProvisioningProfileCreateRequest.provisionSecret input-field-removed the provision secret is generated by the server (256 bits) and returned once by createProvisioningProfile; there is no secret to choose, so omit the field
v0.25.2 device-management ProvisioningProfileUpdateRequest.provisionSecret input-field-removed the provision secret changes only through rotateProvisioningProfileSecret, which returns the new secret once; an edit can no longer replace it
v0.26.0 device-management ProvisioningProfileSecretResult.issuedSecret field-type-changed a provisioning profile that names a trust anchor authenticates devices by certificate and has no secret, so issuedSecret is null for it; a client written against v0.26.0 never creates one, and for every secret profile the field is still a 43-character secret returned once
