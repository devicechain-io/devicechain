# 领域模型 {#domain-model}

DeviceChain 使用少量可组合的概念来建模物理世界。其关键设计是使用**带类型的关系图**表达设备的*上下文*，而不是固定的分配记录。这使模型能够逐步接纳新的实体类型。

## 核心实体 {#core-entities}

- **设备（Device）**：建立连接并上报数据的对象。每台设备都是某种设备类型的实例。
- **设备类型（Device Type）**：分类与身份层。它保存一类设备的名称、外观（图标和颜色），以及用于分组和筛选的分类信息。一个设备类型最多引用一个设备配置文件。
- **设备配置文件（Device Profile）**：能力契约。它是独立且支持版本管理的资源（草稿 → 发布 → 回滚），拥有一类设备的指标、命令和检测规则定义，以及其设备接收的配置键。发布时，这些内容全部固定到新版本中。多个设备类型可以共享同一个配置文件，因此能力配置只需定义一次，即可复用。设备通过 `device → type → profile` 查找其能力。没有配置文件的设备类型仍然有效：它对设备进行分类并控制显示，但不提供带类型的能力契约。
- **资产（Asset）**：设备监测的现实对象，按租户定义的**资产类型**分类。资产类型可以发布支持版本管理的属性模式，并据此验证资产属性。资产构成父子层级，每个资产最多有一个父级，不允许循环。
- **区域（Area）**：有名称的空间或组织位置，按**区域类型**分类。空间边界单独建模为[地理围栏](./geofencing.md)，而不是区域上的字段。
- **客户（Customer）**：组织所有者，按**客户类型**分类。
- **分组（Groups）**：统一的**实体组**收集同一类别的成员（设备、资产、区域或客户），类别在创建分组时选定。成员关系可以是静态的显式成员列表，也可以是动态的、针对成员属性保存的选择器，在读取时求值（参见[分面与动态分组](#facets-and-dynamic-groups)）。

设备、资产、区域、客户和分组采用相同的寻址方式：实体类型加上租户内稳定的令牌。统一地址让关系、分组和事件索引能够通用于这些实体。设备类型和设备配置文件不属于这种可寻址实体；它们是设备通过引用查找的配置。

## 关系 {#relationships}

DeviceChain 不将设备绑定到唯一固定的 `(customer, area, asset)` 分配记录，而是用带类型、有方向的关系连接实体：

- 关系具有**源**、**目标**和**关系类型**。
- 关系类型携带 **`Tracked`** 标志。

`Tracked` 标志至关重要。设备上报事件时，平台会将设备的每条被跟踪关系记录为该事件的**锚点**。锚点是事件锚点集合中的 `(anchor_type, anchor_token)` 条目：目标实体的类型及其在租户内的稳定令牌。

一台设备可以同时持有多条被跟踪关系，例如客户*和*区域*和*资产。读数随后可以按其中任何一个维度查询：“7 号楼的所有温度读数”和“Acme 客户的所有温度读数”都能找到它。锚点在写入时捕获，因此之后重新分配设备不会改变历史数据的归属。

**分配用于组织，而非准入控制。** 已有凭据但尚未分配的设备仍然可以上报遥测数据。其事件会解析为空锚点集合，而不是被丢弃。之后分配设备时，后续事件会获得客户、区域或资产锚点。参见[管理设备分配](../guides/managing-assignments.md)。

## 属性与事件 {#attributes-vs-events}

DeviceChain 将当前状态与历史记录分开：

- **事件**是设备上报的所有内容的只追加时序记录：测量、位置、警报、命令调用与响应，以及状态变更。它们保存在 TimescaleDB 超表中。
- **属性**是实体当前的键值状态，分为三个作用域：
  - `CLIENT`：由设备上报。
  - `SERVER`：仅供平台使用的元数据，设备不可见。
  - `SHARED`：由平台为设备设置。设备配置文件声明为配置项的共享键会作为设备的[配置](../guides/connecting-a-device.md#reserved-device-topics)下发给设备；声明中未列出的共享键永远不会发送。固件和软件更新单独传递，作为[空中（OTA）更新](./over-the-air-updates.md)分配。

## 分面与动态分组 {#facets-and-dynamic-groups}

属性还可以作为**分面**，用于浏览和筛选实体。每个租户的**分面注册表**声明某个实体类别的哪些属性键作为分面，为控制台浏览界面提供筛选维度和值的输入提示。注册表只声明*哪些键*是分面；值仍作为属性保存在实体本身上。

**动态分组**将分类筛选条件转化为保存后自动更新的成员关系。其选择器是基于成员属性的布尔表达式，例如 `attr["climate"] == "arid" && attr["country"] == "US"`。它使用 [CEL](https://github.com/google/cel-go) 编写，与检测引擎使用的表达式语言相同。

保存分组时，平台会验证选择器并限制其计算成本。随后在读取时，将表达式转换为使用索引的数据库查询来确定成员，绝不扫描每个实体。因此，动态分组始终反映当前属性状态，无需维护同步的物化缓存。静态分组则保存显式成员列表。

控制台中的**浏览（Browse）**页面根据分面组合选择器，实时预览匹配数量，并将其保存为动态分组。**分面（Facets）**页面管理注册表。

## 命令 {#commands}

设备配置文件声明设备接受的命令。发出的命令会持久化并跟踪完整生命周期，而不是发出后就不再关注。[命令](./commands.md)介绍了这两部分。

## 将配置文件导出为 W3C Thing Model {#wot-thing-model}

设备配置文件的每个已发布版本都可以导出为 [W3C Web of Things](https://www.w3.org/TR/wot-thing-description11/) **Thing Model**，即描述一类设备的标准 JSON-LD 文档。配置文件描述的是其设备类型下的所有设备，而不是某一台具体设备，因此导出的是 Thing Model 而不是 Thing Description：它不包含设备地址、协议绑定或安全信息，这些是针对单台设备的 Thing Description 才会添加的内容。

- 每个**指标**成为一个只读、可观察的**属性（property）**，以其指标键命名。其数据类型成为属性的类型（`DOUBLE` → `number`、`INT` → `integer`、`BOOLEAN` → `boolean`、`STRING` → `string`），其单位、最小值、最大值和允许值也会保留。指标的**描述符（descriptor）**成为属性的 `@type`，因此诸如 `saref:Temperature` 的语义标签可以传递给能理解它的工具。
- 每个**命令**成为一个**动作（action）**，以其命令键命名。其参数成为动作的 `input`：一个对象模式，每个参数对应一个属性，类型映射方式相同，嵌套参数为嵌套对象，必填参数列为必填。
- 模型的 `version.model` 是配置文件的版本号。指标和命令来自已发布的版本，而该版本不会改变；但模型的 `title` 和 `description` 是配置文件**当前**的名称和描述，因此在配置文件改名后再导出同一版本，会得到不同的标题。
- 如果某个版本声明了 Thing Model 无法表达的约束，导出会被**拒绝**，而不是去掉该约束后继续导出。例如：非数值属性上的数值范围、不是互不相同的文本值列表的允许值，以及无法用该属性类型书写的允许值。拒绝信息会指明相应的指标或命令，方便你在新版本中修正。

在控制台中，打开配置文件的**版本（Versions）**选项卡，在某个版本上选择 **WoT Thing Model** 即可下载。通过 GraphQL，在配置文件版本上选择 `thingModel`；它是以文本形式返回的 JSON-LD：

```graphql
query {
  deviceProfileVersions(token: "pump", limit: 1) {
    version
    thingModel
  }
}
```

## 身份与凭据 {#identity-and-credentials}

设备具有稳定的**身份**，供其他对象引用；身份与用于认证的**凭据**分开保存。凭据可插拔，支持访问令牌、MQTT-basic（用户名 + 密码），以及链到租户所添加[信任锚](./device-certificates.md)的 X.509 客户端证书。因此，设备可以轮换凭据或同时持有多个凭据，而无需改变身份。

无论持有哪些凭据，设备也可以被整体**停用**：在重新启用之前，其事件被丢弃、无法建立新连接、其配置和更新流量被拒绝、发往它的命令被拒绝。参见[停用设备](../guides/device-credentials.md#disabling-a-device)。

凭据中的密钥是**只写**的：注册凭据时提交，读取时绝不返回。这只适用于 MQTT-basic 密码。对于访问令牌，凭据 ID 本身就是持有凭据的证明，因此读取设备凭据需要 `device:write` 权限，而不是 `device:read`。参见[设备凭据](../guides/device-credentials.md#reading-a-credential)。

设备还可以带有可选的 **`externalId`**：客户自己的业务标识，例如 VIN、序列号、GS1 编码或资产标签。它既不同于内部身份，也不同于凭据。它具有以下特点：

- 不透明，没有格式限制；
- 存在时在租户内唯一；
- 绝不用于寻址或认证。

它用于查找与集成：将 DeviceChain 设备与其他系统用于同一物理对象的现有标识匹配起来。

## 事件 {#events}

每个事件记录：

- 上报设备；
- 事件类型；
- 设备上报时间戳与平台接收时间戳；
- 用于幂等接入的可选外部关联 ID（`altId`）；
- 上述已解析关系锚点的集合，即零条或多条 `(anchor_type, anchor_token)` 记录。设备未分配时，集合为空。

事件类别包括测量、位置、警报、命令调用与响应，以及状态变更。

测量是**自描述**的。如果读数匹配设备配置文件上定义的指标，平台会将该指标的单位和数据类型直接写入持久化读数及实时最新已知状态投影。读取测量的消费者无需再次查询配置文件，即可获取其语义（`22.4 °C`，类型为 `DOUBLE`）。
