`dcctl backup <instance> --destination <new-directory>` exports every declared
checkpoint-preserved platform stream, including empty streams and consumers,
and `$MQTT_msgs` when present. Missing platform streams fail closed. It resolves
the installed instance, broker admin credentials and TLS material exactly as
`dcctl ha verify` does; `--kube-context` and `--nats-url` select context and an
optional direct broker connection. The installed broker must have the snapshot
and chunk-acknowledgement permissions generated by this version's admin policy.

For filesystem blobs, supply `--blob-directory <read-only-export-root>` pointing
to a mounted PVC or completed snapshot export. The root contains the instance
directory. A missing instance directory or an incomplete upload is an error.
S3 uses the deployed bucket/endpoint configuration and the operator's standard
AWS credential chain, listing only the instance prefix and using conditional
GETs. This command does not create a PVC export Job or acquire cloud credentials
from service pods.

Blob snapshots are tar files containing `objects/<original-key>` and
`index.json`: original blob Ref (including backend and instance), size, SHA-256,
and S3 content type/version ID when returned. All completed objects under the
instance prefix are copied, including unreferenced content. Each stream snapshot
is a ZIP envelope containing the unchanged native server archive (`snapshot.s2`)
and the API's configuration/state response (`metadata.json`). Both are covered
by the manifest checksum. The native archives come from `$JS.API.STREAM.SNAPSHOT`
with message checksum checking and consumers included (nats.go v1.55.0 has no
snapshot helper). The writer checks all exported files and atomically publishes
`manifest.json` last. Failed exports leave diagnostic files but no manifest;
retry into a new directory. Existing destinations are never overwritten.

Freeze uploads, deletes, producers and consumers before running this export.
This slice does not orchestrate maintenance mode or database recovery cutoffs,
so the files alone do not prove a coordinated recovery checkpoint.

`dcctl backup inspect <backup-set-dir> --verify` reads `manifest.json` and
verifies all listed snapshots locally. Any validation, read, size, or hash error
returns a nonzero exit status, naming the affected entry. No cluster is contacted
and no files are written. `--verify` is required; `--verify=false` is rejected.

Version 1 manifest example:

```json
{
  "version": 1,
  "entries": [
    {
      "kind": "stream",
      "name": "capture",
      "backup_class": "checkpoint-required-if-nonempty",
      "snapshot": "streams/capture.snap",
      "size_bytes": 0,
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
    }
  ]
}
```

All entry fields are required. Kinds are `stream` (including gateway streams),
`bucket` (KV), and `object-store` (an opaque export, not necessarily JetStream).
Classes use `durability.BackupClass` values: only `must-survive` and
`checkpoint-required-if-nonempty` preserve checkpoint content and are accepted.
Rebuildable, ephemeral, missing, and unknown classes are rejected for every kind.
No registry lookup overrides the manifest's declared policy.

Snapshots are distinct regular files at slash-separated paths under the backup
directory; absolute paths, traversal, Windows separators/drive prefixes, and
symlinks escaping the directory are rejected. Sizes are nonnegative integers;
SHA-256 digests are 64 lowercase hexadecimal characters. Resource identities
(`kind`, `name`) and snapshot paths must be unique. Empty inventories, unknown
versions/fields, duplicate JSON keys, malformed JSON, and trailing JSON values are rejected. Snapshots
are hashed as a stream, without loading archives into memory.

Success proves the listed bytes match the manifest. It does not authenticate the
manifest, inspect native archive internals, establish inventory completeness, or
prove a coordinated database/stream/blob recovery checkpoint. This slice defines
no restore operation or separate COMPLETE marker; the manifest is published last.
