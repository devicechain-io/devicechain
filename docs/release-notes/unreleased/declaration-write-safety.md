## en

- **`dcctl upgrade` now refuses while another dcctl run holds the cluster lock, instead of warning and carrying on.** It takes the lock before its first write and checks the cluster's operator again while it holds it, so a `dcctl install` cannot move the operator underneath it. The lock is one per cluster, so two upgrades of DIFFERENT instances on the same cluster can no longer run at the same time: run them one after the other. An account without `create` and `delete` on `leases.coordination.k8s.io` in `dc-k8s-system` is now refused rather than warned. A run that was killed leaves the lock behind: take it with `dcctl instances reclaim` (it waits a lease duration and asks you to type the holder back). A run that is still alive keeps renewing and cannot be reclaimed: stop that process first. Two related changes: `dcctl instances release` refuses when the cluster's operator does not match this dcctl (pass `--force` to release anyway; a cluster with no operator at all is still let through, which is what the command is for, and it now needs `get` on `customresourcedefinitions`), and the dcctl writes that replace an instance declaration whole (bootstrap, upgrade and their annotation records) refuse a declaration that carries fields this dcctl does not know, rather than erasing them. Use the dcctl that matches the cluster.

## es

- **`dcctl upgrade` ahora se niega mientras otra ejecución de dcctl tiene el bloqueo del clúster, en lugar de avisar y continuar.** Toma el bloqueo antes de su primera escritura y vuelve a comprobar el operador del clúster mientras lo tiene, de modo que un `dcctl install` no puede mover el operador por debajo. El bloqueo es uno por clúster, así que dos actualizaciones de instancias DISTINTAS del mismo clúster ya no pueden ejecutarse a la vez: ejecútalas una tras otra. Una cuenta sin `create` y `delete` sobre `leases.coordination.k8s.io` en `dc-k8s-system` ahora se rechaza en lugar de recibir un aviso. Una ejecución que fue terminada deja el bloqueo atrás: tómalo con `dcctl instances reclaim` (espera la duración de un lease y te pide que escribas de vuelta el titular). Una ejecución que sigue viva lo sigue renovando y no se puede reclamar: detén antes ese proceso. Dos cambios relacionados: `dcctl instances release` se niega cuando el operador del clúster no coincide con este dcctl (pasa `--force` para liberar de todos modos; un clúster sin ningún operador se sigue dejando pasar, que es para lo que existe el comando, y ahora necesita `get` sobre `customresourcedefinitions`), y las escrituras de dcctl que reemplazan una declaración de instancia entera (bootstrap, upgrade y sus registros de anotaciones) rechazan una declaración que lleva campos que este dcctl no conoce, en lugar de borrarlos. Usa el dcctl que coincide con el clúster.

## zh-CN

- **当另一个 dcctl 运行持有集群锁时，`dcctl upgrade` 现在会拒绝执行，而不是发出警告后继续。** 它在第一次写入之前获取锁，并在持有锁时再次检查集群的 Operator，因此 `dcctl install` 无法在其运行期间更换 Operator。每个集群只有一把锁，因此同一集群上*不同*实例的两次升级不能再同时运行：请依次执行。在 `dc-k8s-system` 中对 `leases.coordination.k8s.io` 没有 `create` 和 `delete` 权限的账户，现在会被拒绝而不是仅收到警告。被终止的运行会留下锁：请用 `dcctl instances reclaim` 获取它（该命令会等待一个租约时长，并要求你输入持有者标识）。仍在运行的运行会持续续约，无法被回收：请先停止该进程。两项相关变更：当集群的 Operator 与当前 dcctl 不匹配时，`dcctl instances release` 会拒绝执行（传入 `--force` 可强制释放；完全没有 Operator 的集群仍然放行，这正是该命令的用途；它现在需要对 `customresourcedefinitions` 的 `get` 权限）；dcctl 整体替换实例声明的写入（初始化、升级及其注解记录）如果遇到含有当前 dcctl 不认识字段的声明，会拒绝写入，而不是将其删除。请使用与集群匹配的 dcctl。
