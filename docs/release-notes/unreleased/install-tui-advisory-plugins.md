## en

- **The install terminal UI's existing-cluster checks authenticate through credential plugins.** A context that gets its credentials from an exec plugin, as GKE, EKS and AKS contexts usually do, no longer reads NOT CHECKED for authentication and permissions: the advisory checks run the plugin themselves, never interactively (no terminal, nothing on its input), for at most 10 seconds, and stop it together with everything it started when that time is up or you leave the screen. The credential it prints is used only for the context's API server, over the same read-only, redirect-free, proxy-free connection as any other credentials, never after it expires, and is never shown. A plugin whose entry says `interactiveMode: Always` is not run (NOT CHECKED), a plugin that is not installed reads WARN, and one that fails or prints no usable credential reads UNKNOWN, with its error message shown with any credentials in its URLs removed. Legacy `auth-provider` entries are still never run. The registry checks now follow the plan: a component the plan leaves out (monitoring under Compact or `--no-monitoring`, the CloudNativePG operator under `--no-cnpg`, cert-manager under Compact without TLS) is not checked and cannot warn, the Traefik chart repository is checked, and the ingress-nginx one, which a new install does not use, is not. On Windows, a refused connection now reads WARN ("refused the connection") instead of UNKNOWN.

## es

- **Las comprobaciones del clúster existente de la interfaz de terminal de la instalación se autentican mediante plugins de credenciales.** Un contexto que obtiene sus credenciales de un plugin exec, como suelen hacerlo los contextos de GKE, EKS y AKS, ya no muestra NOT CHECKED en autenticación y permisos: las comprobaciones de consejo ejecutan el plugin ellas mismas, nunca de forma interactiva (sin terminal y sin nada en su entrada), durante 10 segundos como máximo, y lo detienen junto con todo lo que haya iniciado cuando se agota ese tiempo o sales de la pantalla. La credencial que imprime solo se usa para el servidor de la API del contexto, por la misma conexión de solo lectura, sin redirecciones y sin proxy que cualquier otra credencial, nunca después de que caduque, y nunca se muestra. Un plugin cuya entrada dice `interactiveMode: Always` no se ejecuta (NOT CHECKED), un plugin que no está instalado se lee como WARN, y uno que falla o no imprime una credencial utilizable se lee como UNKNOWN, con su mensaje de error mostrado sin las credenciales que lleven sus URL. Las entradas heredadas `auth-provider` siguen sin ejecutarse nunca. Las comprobaciones de registros ahora siguen el plan: un componente que el plan deja fuera (la monitorización con Compact o `--no-monitoring`, el operador CloudNativePG con `--no-cnpg`, cert-manager con Compact sin TLS) no se comprueba y no puede avisar, se comprueba el repositorio de charts de Traefik, y el de ingress-nginx, que una instalación nueva no usa, no. En Windows, una conexión rechazada ahora se lee como WARN ("refused the connection") en lugar de UNKNOWN.

## zh-CN

- **安装终端界面的现有集群检查现在可以通过凭据插件进行身份验证。** 通过 exec 插件获取凭据的上下文（GKE、EKS 和 AKS 的上下文通常如此）的身份验证和权限两行不再显示 NOT CHECKED：这些建议性检查会自行运行该插件，从不以交互方式运行（没有终端，输入为空），最长 10 秒；时间用完或您离开该屏幕时，插件及其启动的所有进程都会被一并停止。插件输出的凭据只用于该上下文的 API 服务器，使用与其他凭据相同的只读、不跟随重定向、不经过代理的连接，过期后不再使用，并且从不显示。条目中写明 `interactiveMode: Always` 的插件不会运行（NOT CHECKED），未安装的插件显示为 WARN，运行失败或没有输出可用凭据的插件显示为 UNKNOWN，并会显示其错误信息，其中 URL 所带的凭据已被移除。旧式的 `auth-provider` 条目仍然从不运行。仓库检查现在跟随计划：计划不包含的组件（Compact 或 `--no-monitoring` 下的监控，`--no-cnpg` 下的 CloudNativePG operator，不带 TLS 的 Compact 下的 cert-manager）不会被检查，也不会产生警告；会检查 Traefik 的 chart 仓库，而不再检查新安装不会使用的 ingress-nginx 仓库。在 Windows 上，被拒绝的连接现在显示为 WARN（"refused the connection"），而不是 UNKNOWN。
