## en

- **The console and `@devicechain/client` can refuse requests an instance cannot serve.** A console built for a newer release, pointed at an older instance, used to send requests the instance did not understand and fail with an opaque error. Negotiation asks each GraphQL endpoint for the schema it serves, using an authenticated `OPTIONS` request, and checks every request against it before sending. A request that uses a field or input the instance lacks is refused, nothing is sent, and the error says what is missing. Nothing is trimmed or rewritten. An instance older than v1.9.0 does not offer this discovery, so its release cannot be confirmed: the request is refused with an error naming v1.9.0 and is not sent on a guess. The console turns negotiation on only where it can be a different release from its instance: under `vite dev`, or in a build made with `VITE_SCHEMA_NEGOTIATION=on`. A console served by its own instance stays off, so a proxy that answers `OPTIONS` cannot break it. Sign-in, token refresh and live subscriptions are not checked. For your own application, `@devicechain/client` adds `enableSchemaNegotiation` (with an optional `release`), `disableSchemaNegotiation`, `resetSchemaNegotiation`, `SchemaSkewError` and `isSchemaSkewError`; it is off unless you enable it and needs the `graphql` peer package you already install. If a CORS proxy or web application firewall answers `OPTIONS` itself, discovery fails and negotiation refuses every request, so let `OPTIONS` reach the GraphQL endpoints. The `/dash` viewer app does not enable it yet.

## es

- **La consola y `@devicechain/client` pueden rechazar las solicitudes que una instancia no puede atender.** Una consola creada para una versión más reciente y conectada a una instancia más antigua enviaba solicitudes que la instancia no entendía y fallaba con un error poco claro. La negociación pide a cada endpoint GraphQL el esquema que sirve, mediante una solicitud `OPTIONS` autenticada, y comprueba cada solicitud con él antes de enviarla. Una solicitud que usa un campo o una entrada que la instancia no tiene se rechaza, no se envía nada y el error indica qué falta. No se recorta ni se reescribe nada. Una instancia anterior a v1.9.0 no ofrece este descubrimiento, por lo que no se puede confirmar su versión: la solicitud se rechaza con un error que menciona v1.9.0 y no se envía a ciegas. La consola activa la negociación solo donde puede ser una versión distinta de su instancia: con `vite dev` o en una compilación hecha con `VITE_SCHEMA_NEGOTIATION=on`. Una consola servida por su propia instancia la mantiene desactivada, de modo que un proxy que responda a `OPTIONS` no puede romperla. No se comprueban el inicio de sesión, la renovación de tokens ni las suscripciones en vivo. Para su propia aplicación, `@devicechain/client` añade `enableSchemaNegotiation` (con un `release` opcional), `disableSchemaNegotiation`, `resetSchemaNegotiation`, `SchemaSkewError` e `isSchemaSkewError`; está desactivado salvo que lo habilite y requiere el paquete par `graphql` que ya instala. Si un proxy CORS o un firewall de aplicaciones web responde a `OPTIONS` por sí mismo, el descubrimiento falla y la negociación rechaza todas las solicitudes, así que deje que `OPTIONS` llegue a los endpoints GraphQL. La aplicación de visualización `/dash` todavía no la habilita.

## zh-CN

- **控制台和 `@devicechain/client` 可以拒绝实例无法处理的请求。** 为较新版本构建的控制台连接到较旧的实例时，过去会发送实例无法理解的请求，并以难以理解的错误失败。协商功能通过经过身份验证的 `OPTIONS` 请求，向每个 GraphQL 端点获取其提供的 schema，并在发送前用它检查每个请求。使用了实例所没有的字段或输入的请求会被拒绝，不会发送任何内容，错误信息会指出缺少什么。不会裁剪或改写任何内容。早于 v1.9.0 的实例不提供这种发现，因此无法确认其版本：请求会被拒绝，并给出提到 v1.9.0 的错误，而不会凭猜测发送。控制台仅在可能与其实例版本不同的情况下启用协商：使用 `vite dev` 时，或使用 `VITE_SCHEMA_NEGOTIATION=on` 构建时。由其自身实例提供服务的控制台保持关闭，因此自行应答 `OPTIONS` 的代理不会使其出错。登录、令牌刷新以及实时订阅不做检查。对于您自己的应用，`@devicechain/client` 新增了 `enableSchemaNegotiation`（可选 `release` 参数）、`disableSchemaNegotiation`、`resetSchemaNegotiation`、`SchemaSkewError` 和 `isSchemaSkewError`；除非您启用，否则默认关闭，并且需要您已安装的 `graphql` 对等依赖包。如果 CORS 代理或 Web 应用防火墙自行应答 `OPTIONS`，发现会失败，协商会拒绝所有请求，因此请让 `OPTIONS` 到达 GraphQL 端点。`/dash` 查看器应用暂未启用该功能。
