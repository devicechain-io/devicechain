# Towerpulse art source

The Towerpulse models (a five-floor tower, a two-floor lab annex, rooftop air handlers, chillers,
furniture, office workers and the campus ground) are generated by the Blender Python code in this
directory, with the same method as the Sitepulse machines. Nothing here is hand-modelled: change the
code, rebuild, and commit the regenerated `.glb` files together with the code change, so the models
in `Assets/Towerpulse/Art/Models/` always match their source.

| File | Purpose |
|---|---|
| `towerpulse_kit.py` | Shared kit: the authoring frame, the part builders, the material palette (glass included), the lower-detail (LOD1) pass, glTF export and the report |
| `layout.py` | The campus on paper, and the one source for it: footprints, the 24 zones and their node names, furniture and seat placement, rooftop-unit and chiller positions, the ground plan. Pure Python |
| `build.py` | Builds the models (each in a Blender of its own), runs the checks, exports, optionally installs |
| `models/buildings.py` | `tower`, `annex` |
| `models/equipment.py` | `ahu`, `chiller` |
| `models/furniture.py` | `desk`, `meeting_table`, `chair` |
| `models/people.py` | `person_standing_a/b`, `person_seated_a/b` |
| `models/ground.py` | `campus_ground` |
| `preview.py` | Cycles (CPU) preview renders of the whole campus, assembled from the built `.glb` files |

The same scenario drives what the models stand for: 24 VAV zones (20 in the tower, 4 in the annex), 3
air handlers and 2 chillers. Zone ids come from the scenario (`tower-f4-east`, `annex-f1-laba`); the
node names below are derived from them by `layout.node_name`.

## Requirements

- **Blender 4.5 LTS** (built and checked with 4.5.14). The scripts run headless; no Blender UI is
  needed. Linux, Windows and macOS builds all work.
- Rendering uses Cycles on the CPU, so it works on a machine without a GPU.

## Building

From this directory:

```
blender --background --python build.py -- all --install
```

`all` (or no name) builds every model; give names (`tower annex`) to build some. Each model is built in
a fresh Blender, so a rebuild is byte-identical to the last one: a changed `.glb` is a changed model.
Output goes to `out/` (ignored by git):

- `<model>.glb` and `<model>_LOD1.glb`: the full and lower-detail models, same node tree;
- `<model>.blend`: the generated scene, for inspection in Blender;
- `models_check.json`: triangle counts, bounding boxes and the result of every check;
- `campus_layout.json`: the layout, for Unity.

`--install` (only when every check passes) copies the `.glb` files to `../Assets/Towerpulse/Art/Models/`
and the layout to `../Assets/Towerpulse/Data/campus_layout.json`. The Unity Editor creates the `.meta`
files when it next opens the project; none are committed from here.

The build exits non-zero if any check fails. The checks:

| Check | What it proves |
|---|---|
| `nodes_in_glb` | every node the model promises is in the exported file, both LODs |
| `one_node_per_zone` | exactly one `Zone_*` node per zone id, none missing, none extra |
| `zones_disjoint`, `zones_inside_slab`, `zone_areas_plausible` | zone volumes do not overlap, stay inside the slab, and are 70 to 100 m2 |
| `floor_to_floor_3p8` | the floors are 3.8 m apart |
| `no_open_geometry` | no holes (boundary edges), degenerate faces or loose vertices in any mesh |
| `budget` | LOD0 triangles under the model's limit |
| `lod_hierarchy_match`, `pivots_axis_aligned`, `glb_root_identity` | the rig rules below |
| `root_at_origin` | Root is at the origin and the model stands on its ground |
| `blend_materials` | the glass and the zone tint export as alpha-blended, everything else opaque |

## Preview renders

```
blender --background --python preview.py -- [hero] [closeup] [roof] [--samples 128] [--res 1600x900]
```

Imports the built `.glb` files from `out/`, places them from the layout, cuts the south and east
facades away, tints the zones by a made-up temperature (Tower F4-East is the hot one), seats people
and lights it as dusk. Writes `out/towerpulse_<shot>.png`. It is a look check for the art, not the
Unity scene.

## Conventions

The authoring frame is Unity's: metres, X east, Y up, Z north, with every model's origin on the ground
(or the roof) under the centre of its footprint. The kit converts to Blender's frame internally, and the
glTF export and import convert back, so the models import into Unity facing +Z with no root rotation.
Buildings are placed unrotated.

Every functional part is an empty at its pivot, at identity rotation at rest. Geometry hangs under it
as `<Node>_LOD0` and `<Node>_LOD1`; the two levels are two files with the same node tree, which Unity
pairs by path. Palette: neutral and unbranded (`M_Concrete`, `M_Plaster_Warm`, `M_Steel_*` ...); all
materials are shared across models by name.

**Glass under URP.** `M_Glass` and `M_ZoneTint` carry an alpha below 1, which the exporter writes as
glTF `alphaMode: BLEND`; glTFast turns that into a transparent URP material. No transmission extension
is used (URP would need an opaque-texture pass for it). Backface culling is on for both.

### Tower and annex (`tower.glb`, `annex.glb`)

```
Root
  Floor_F<n>                  pivot at floor level, footprint centre         n = 1..5 (annex 1..2)
    Slab_F<n>                 the floor slab; its top face is the floor
    Zone_F<n>-<Wing>          room volume, pivot at the room's floor centre
    Anchor_F<n>-<Wing>        empty 2.6 m above the floor centre, for a card or a label
  Roof                        pivot at the roof level; slab, membrane, parapet
    Mount_<device id>         empty where a rooftop unit stands
  Facade_North / East / South / West
  Core, CoreLifts, CoreStairs (the annex has Core only: its stair tower is outside the footprint)
  Entrance
```

- **Floor level** of floor n is `y = (n - 1) * 3.8`; the roof is at 3.8 * floors.
- **Zone node names.** Tower: `Zone_F<floor>-<North|East|South|West>`, annex: `Zone_F<floor>-<LabA|LabB>`.
  Scenario id `tower-f4-east` is `Zone_F4-East` in `tower.glb`; `annex-f1-laba` is `Zone_F1-LabA` in
  `annex.glb`. `Anchor_...` swaps the `Zone_` prefix for `Anchor_`.
- **Tinting.** A zone's mesh is one box of `M_ZoneTint` (pale, alpha 0.22). Tint it with a
  `MaterialPropertyBlock` per renderer (or an instanced material per zone); do not edit the shared
  material. Volumes sit 0.04 m inside their room and 0.03 to 3.45 m above the floor, so neighbours never
  share a face.
- **Layout of a tower floor.** Four 12 x 7 m wings pinwheel round a 5 x 5 m core (north, east, south,
  west by the side of the building they face; the east wing is the one on the +X face and reaches
  furthest north). Annex: two 9 x 10 m labs, LabB west and LabA east.
- **The cutaway.** Each facade side is its own node. Disable the GameObjects of the sides that face the
  camera (south and east for the hero angle) and the interiors show; the slabs, the core and the zone
  volumes stay. `Entrance` is not part of any facade, so it stays too. Facade mullions and the core's
  frames are LOD0-only detail.
- **Placement.** Place `tower.glb` and `annex.glb` at the building `position` in `campus_layout.json`,
  unrotated.

### Rooftop air handler and chiller (`ahu.glb`, `chiller.glb`)

```
ahu:      Root / Body, Fan, Anchor
chiller:  Root / Body, Fan_1 .. Fan_4, StatusLamp, Anchor
```

- `Fan`, `Fan_n`: pivot at the fan hub; **spin about the node's local Y axis** (Unity). The blades are
  pitched so a turning fan reads as one; shroud and guard are in `Body` and do not move.
- `StatusLamp`: a small emissive lamp (`M_Light_Warm`) on a post; change its emission colour for
  running / tripped.
- One `ahu.glb` is placed three times and one `chiller.glb` twice. Rooftop units go at the tower's and
  annex's `Mount_<device id>` nodes (also listed, in world coordinates, in the layout); chillers at
  their world positions. `ahu-tower-low` serves floors 1 to 3, `ahu-tower-high` floors 4 and 5.

### Furniture and people

- Every one is `Root / Body`, origin on the floor at the centre of the footprint.
- `chair` faces +Z (back at -Z); `desk`'s user sits at -Z and faces +Z; `meeting_table` is symmetric.
- `person_standing_*` stands on the floor between the feet; `person_seated_*` has its origin on the floor
  under the pelvis, so it drops onto a chair placed at the same X, Z (seat top 0.50 m). Both face +Z.
  Variant `a` and `b` use different clothes, hair and skin tone materials.
- `campus_layout.json` lists every desk, chair and meeting table per zone (building-local x, z, yaw)
  and the chairs again as `seats`, in order; the hot zone (F4-East, capacity 6) has a meeting table with
  six chairs.

### Campus ground (`campus_ground.glb`)

`Lawn`, `Plaza`, `Paths`, `Planters`, `Trees`, `Bollards`, `BollardLamps` under Root, origin at the
campus origin, placed unmoved. The lawn top is at y = -0.15 and paving at y = -0.03, so floor level 0
of the buildings stands a little proud. `BollardLamps` is its own node so the scene can dim it by day.

### Budgets

Triangle limits at LOD0: tower 7000, annex 3000, chiller 2000, ahu 1200, ground 7000, people 600,
furniture 300. The numbers actually built are in `out/models_check.json`.

## Layout

`layout.py` is the single place the campus is described: change a zone's size, a mount position or a
path there and rebuild, and the models, the checks, the preview and `campus_layout.json` follow. The
campus in `layout.py` is drawn around the scenario's device list (zone, air-handler and chiller ids);
`campus_layout.json` carries those ids, so the Unity side can look nodes up by id and never by position.
