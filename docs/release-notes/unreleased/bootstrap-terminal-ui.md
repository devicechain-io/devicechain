## en

- **A terminal UI for `dcctl bootstrap` (opt-in).** `dcctl bootstrap local <instance> --ui=tui` creates the instance in a full-screen terminal UI: the instance and root-key escrow choices, seeded from the command line; a review of the exact bootstrap with its equivalent command, which only **Approve and create the instance** starts; the bootstrap's stages as they run, with the escrow passphrase asked for on screen and never shown; then the escrow receipt, the one-time first-login password and the instance summary. Every flag the screens do not choose is carried into the run unchanged, and an escrow path inside the instance's state directory is refused before the approval. With `--yes` or `--dev` it shows progress only. `--ui` on `dcctl bootstrap` has the same values, default (`plain`) and fallbacks as on `dcctl install`: without it, off an interactive terminal, under CI, with `TERM=dumb` and with `--dry-run`, `dcctl bootstrap` prints, prompts and exits exactly as before, and the escrow passphrase still comes from `--escrow-passphrase-file`, then `DCCTL_ESCROW_PASSPHRASE`, then a person. The `dcctl install --ui=tui` success screen and `dcctl setup local` now name the `dcctl bootstrap … --ui=tui` command as the next step.

## es

- **Una interfaz de terminal para `dcctl bootstrap` (opcional).** `dcctl bootstrap local <instance> --ui=tui` crea la instancia en una interfaz de terminal a pantalla completa: las opciones de la instancia y del depósito de la clave raíz, rellenadas a partir de la línea de comandos; una revisión del bootstrap exacto con su comando equivalente, que solo inicia **Aprobar y crear la instancia**; las etapas del bootstrap mientras se ejecutan, con la frase de paso del depósito pedida en pantalla y nunca mostrada; y después el comprobante del depósito, la contraseña de primer inicio de sesión de un solo uso y el resumen de la instancia. Toda opción que las pantallas no eligen se lleva a la ejecución sin cambios, y una ruta de depósito dentro del directorio de estado de la instancia se rechaza antes de la aprobación. Con `--yes` o `--dev` solo muestra el progreso. `--ui` en `dcctl bootstrap` tiene los mismos valores, el mismo valor predeterminado (`plain`) y las mismas alternativas que en `dcctl install`: sin ella, fuera de un terminal interactivo, en CI, con `TERM=dumb` y con `--dry-run`, `dcctl bootstrap` imprime, pregunta y sale exactamente igual que antes, y la frase de paso del depósito sigue saliendo de `--escrow-passphrase-file`, después de `DCCTL_ESCROW_PASSPHRASE` y después de una persona. La pantalla de éxito de `dcctl install --ui=tui` y `dcctl setup local` indican ahora el comando `dcctl bootstrap … --ui=tui` como siguiente paso.

## zh-CN

- **`dcctl bootstrap` 的终端界面（可选）。** `dcctl bootstrap local <instance> --ui=tui` 在全屏终端界面中创建实例：实例和根密钥托管的选项按命令行预先填写；对确切的 bootstrap 进行审核并显示其等效命令，只有**批准并创建实例**才会开始运行；运行时显示 bootstrap 的各个阶段，托管口令在屏幕上询问且从不显示；随后显示托管回执、一次性的首次登录密码和实例摘要。屏幕不选择的每个标志都会原样带入运行，位于实例状态目录之内的托管路径会在批准之前被拒绝。使用 `--yes` 或 `--dev` 时只显示进度。`dcctl bootstrap` 上的 `--ui` 与 `dcctl install` 上的取值、默认值（`plain`）和回退规则相同：不加该标志、不在交互式终端中、在 CI 中、`TERM=dumb` 以及使用 `--dry-run` 时，`dcctl bootstrap` 的输出、提示和退出方式与以前完全相同，托管口令仍依次来自 `--escrow-passphrase-file`、`DCCTL_ESCROW_PASSPHRASE` 和人工输入。`dcctl install --ui=tui` 的成功屏幕和 `dcctl setup local` 现在会把 `dcctl bootstrap … --ui=tui` 命令作为下一步给出。
