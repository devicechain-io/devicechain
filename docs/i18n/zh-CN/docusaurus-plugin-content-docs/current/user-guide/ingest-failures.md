# 摄取失败 {#ingest-failures}

**摄取失败**页面按时间从新到旧列出平台拒绝或无法存储的事件。当设备声称正在发送却看不到任何数据时，请打开它：页面会告诉你平台是否拒绝了这些事件，以及原因。本章面向管理设备的成员。

它是一份报告，而不是队列。不会重新发送任何内容，原始事件也不保存在你租户的数据中。排除原因后，设备之后的事件就会被接受。

## 谁可以查看 {#who}

该页面需要 `device:write` 授权，即管理设备、因而能对拒绝采取行动的成员所持有的授权。每个成员都拥有的只读基础权限不包含它，访问范围仅限于部分客户的成员也看不到它。没有该授权的成员打开页面时会看到一条说明，页面不会向平台发出任何请求。

## 打开页面 {#open}

在侧边栏选择 **Monitor → 摄取失败**。页面也可以带着筛选条件打开：当某台设备的事件在过去 24 小时内被拒绝时，该设备的详情页会链接到这里并带上该设备；设备配置文件的**解码器**选项卡则会带上原因**解码失败**链接到这里。

## 阅读一行 {#rows}

每一行是一个被拒绝的事件。

| 列 | 含义 |
| --- | --- |
| **记录时间** | 平台记录该次拒绝的时间。这是平台的时钟，而不是设备的时钟。 |
| **原因** | 事件被拒绝的原因。原因为**其他原因**的行还会显示其原因代码。 |
| **设备令牌** | 发送方所指明的令牌。这只是发送方的声明，并不证明该设备存在。显示**此原因的更多记录**的行代表超出下文洪峰上限的记录。 |
| **平台返回的信息** | 平台自己的措辞，已缩短。其下方的**原始事件已不再保留；只剩下这份摘要。**或**原始内容未被保留。**说明事件本身的去向。 |
| **另有合并** | **+N 条**：同一设备、同一原因的更多记录有多少条被计入这一行。 |

## 原因 {#reasons}

表格上方的标签就是各个原因。每个标签显示平台在所选时间范围内统计到的该原因记录数，悬停提示会说明其含义。选择一个标签即可只显示该原因；再次选择它，或选择**所有原因**，即可清除筛选。选定某个原因后，页面还会列出受影响最多的设备。

| 原因 | 发生了什么 |
| --- | --- |
| **未知设备** | 没有任何设备拥有发送方所指明的令牌。请注册该设备，或更正它发送的令牌。 |
| **凭据被拒绝** | 设备出示的凭据缺失或不正确。请检查设备的凭据。 |
| **不是此网关的设备** | 网关为一个未分配给它或不存在的设备发布了数据。 |
| **设备已禁用** | 设备存在，但已被禁用。 |
| **无效消息** | 消息无法读取，或其中的某个值被拒绝。错误文本会说明是哪一种。 |
| **平台错误** | 事件所需的某个平台服务无法访问，或存储事件失败。无法在设备端解决；请告知你的运维人员。 |
| **集成别名已更改** | 某个集成的事件指明了一台设备，但该设备已不再持有用于匹配它的别名。 |
| **解码失败** | 负载解码器无法把一条上行消息转换为读数。错误开头会说明原因。请打开该设备类型的配置文件的**解码器**选项卡，查看保留的失败记录并进行测试。 |
| **其他原因** | 此版本控制台没有对应措辞的原因。该行会带有其原因代码。 |

各个原因分别应检查什么，请参阅[为什么我的设备数据没有出现](../guides/why-isnt-my-data-showing-up.md#reasons)。

## 缩小列表范围 {#filters}

- **时间范围**：**过去 1 小时**、**过去 24 小时**（默认）或**过去 7 天**。平台按运维人员设定的保留期保存这些记录，默认为 7 天，因此更长的范围只会显示仍然保留的记录。
- **原因**：上文所述的标签。
- **设备**：在**按设备令牌筛选…**中输入设备令牌，只查看该设备被拒绝的记录。

列表每页显示 25 行。如果没有匹配项，页面会这样告知，并补充说明：数据因其他原因缺失的设备不会列在这里，例如已禁用设备的事件会被丢弃并计数，而不会列出。

## 为什么一行可能代表很多事件 {#flood-bound}

只要有一把错误的凭据，整个设备群每秒就可能被拒绝数千个事件，而把每一条都保留下来的列表将毫无用处。因此，平台对每台设备的每个原因每小时最多保留 10 条记录，其余的计入其中最新的一条（**+N 条**）。对每个原因，跨所有设备每小时最多逐条列出 1,000 条记录；其余的计入一行标为**此原因的更多记录**的单独行中。原因标签上的数字包含所有被合并的记录。

## 命令行，以及死信 {#cli}

`dcctl events failed` 以租户成员的身份读取同样的记录，同样需要 `device:write`，`--summary` 会像标签一样按原因统计。请参阅[命令参考](../reference/dcctl.md#dcctl-events-failed)。

这些记录不是死信（dead letter）。摄取失败是在入口处被拒绝的事件，记录由你自己读取。死信则是平台服务在接受消息之后放弃处理的消息，保留给运维人员；它通过 `dcctl dead-letters` 读取，不会列在这里。
