## en

- **A password set by accepting an invitation now signs in only to the tenants that vouched for it.** When a new person accepts a tenant invitation with a password, that password now opens that tenant, and any other tenant whose invitation the person later accepts by signing in with it. It no longer opens a membership another tenant attached to the same address in some other way, such as an invitation that was revoked before the member was enabled by hand. Those memberships are left out of the sign-in's tenant list and refused when selected. Single sign-on is not affected. While an account carries such a password, the operator's `addMembership` and `setSystemRoles` (with any role) refuse it with the error code `INVITATION_PASSWORD`. Setting the password with `setPassword`, or removing it with `clearPassword`, lifts the restriction and lets both through.
- **Existing accounts are marked by the upgrade.** The upgrade cannot tell an invitation password from one the operator set, so it marks every account that has a password, has no system role, and either has an invitation or has no membership. Such an account keeps every tenant whose invitation it accepted and every membership the operator added before the upgrade, and loses only the memberships that were enabled without an accepted invitation. A password accepted through an invitation on a pod of the previous release while the rolling upgrade is under way is not marked. If you need to, you can reset such an account with `setPassword` once the upgrade is done.

## es

- **Una contraseña establecida al aceptar una invitación ahora solo inicia sesión en los inquilinos que respondieron por ella.** Cuando una persona nueva acepta la invitación de un inquilino con una contraseña, esa contraseña abre ese inquilino y cualquier otro cuya invitación la persona acepte después iniciando sesión con ella. Ya no abre una membresía que otro inquilino haya asociado a la misma dirección de otra forma, como una invitación revocada antes de que el miembro se habilitara a mano. Esas membresías no aparecen en la lista de inquilinos del inicio de sesión y se rechazan al seleccionarlas. El inicio de sesión único no se ve afectado. Mientras una cuenta tenga una contraseña así, `addMembership` y `setSystemRoles` (con cualquier rol) del operador la rechazan con el código de error `INVITATION_PASSWORD`. Establecer la contraseña con `setPassword`, o eliminarla con `clearPassword`, levanta la restricción y deja pasar ambas.
- **La actualización marca las cuentas existentes.** La actualización no puede distinguir una contraseña de invitación de una que estableció el operador, así que marca toda cuenta que tenga contraseña, no tenga rol de sistema y tenga una invitación o ninguna membresía. Esa cuenta conserva todos los inquilinos cuya invitación aceptó y todas las membresías que el operador añadió antes de la actualización, y solo pierde las membresías habilitadas sin una invitación aceptada. Una contraseña aceptada mediante una invitación en un pod de la versión anterior durante la actualización progresiva no queda marcada. Si hace falta, puede restablecer esa cuenta con `setPassword` cuando termine la actualización.

## zh-CN

- **通过接受邀请设置的密码现在只能登录为其担保的租户。** 新用户使用密码接受某个租户的邀请后，该密码可以进入该租户，以及该用户之后用此密码登录并接受其邀请的其他租户。它不再能进入另一个租户以其他方式关联到同一地址的成员身份，例如邀请被撤销后又被手动启用的成员。这些成员身份不会出现在登录的租户列表中，选择时会被拒绝。单点登录不受影响。账户带有这种密码时，运维人员的 `addMembership` 和 `setSystemRoles`（任何角色）会以错误代码 `INVITATION_PASSWORD` 拒绝。用 `setPassword` 设置密码，或用 `clearPassword` 移除密码，即可解除限制，两者随后都能执行。
- **升级会标记现有账户。** 升级无法区分邀请设置的密码和运维人员设置的密码，因此会标记所有有密码、没有系统角色、并且有邀请或没有任何成员身份的账户。这类账户保留其已接受邀请的所有租户以及升级前运维人员添加的所有成员身份，只失去未经接受邀请就被启用的成员身份。滚动升级期间在上一版本的 Pod 上通过邀请接受的密码不会被标记；如有需要，可在升级完成后用 `setPassword` 重置该账户。
