## en

- **`dcctl install --output json` keeps its guarantees at the edges.** The exit status always matches the stream's final verdict, `0` or `1`, even when a tool the install ran was killed or dcctl itself failed unexpectedly, and the stream still ends with its summary line in that case; text output also exits only `0` or `1` again. `--help` with `--output json` prints the help on stderr and leaves stdout empty. Nothing the install runs can read stdin, so a kubeconfig exec credential plugin runs non-interactively. A kubeconfig dcctl cannot parse is now reported by its path, without the parser's reason, which could quote the tokens and passwords in the file, in both output formats, and the kubeconfig's credentials are also redacted from the stream's log lines. With `--output json`, the error printed on stderr and everything else that reaches dcctl's own stdout and stderr during the run, a kubeconfig exec credential plugin's stderr included, are redacted too; with `--output text`, the install's own output and its error are. A kubeconfig that cannot be read or turned into a client is reported by the kind of problem, the file and the context name. A value too short to redact (under 4 bytes) is warned about rather than silently left. The [install event stream reference](../reference/install-events.md) now lists every field of every event and describes how progress is coalesced and when an interrupted OpenTofu command can outlive the run.

## es

- **`dcctl install --output json` mantiene sus garantías en los casos límite.** El código de salida siempre coincide con el veredicto final del flujo, `0` o `1`, incluso cuando se mató una herramienta que ejecutó la instalación o el propio dcctl falló de forma inesperada, y en ese caso el flujo también termina con su línea de resumen; la salida de texto vuelve a salir solo con `0` o `1`. `--help` con `--output json` imprime la ayuda en stderr y deja stdout vacío. Nada de lo que ejecuta la instalación puede leer stdin, así que un plugin de credenciales exec del kubeconfig se ejecuta de forma no interactiva. Un kubeconfig que dcctl no puede analizar se informa ahora por su ruta, sin el motivo del analizador, que podía citar los tokens y contraseñas del archivo, en ambos formatos de salida, y las credenciales del kubeconfig también se eliminan de las líneas de registro del flujo. Con `--output json`, el error que se imprime en stderr y todo lo demás que llega a la stdout y la stderr de dcctl durante la ejecución, incluida la stderr de un plugin de credenciales exec del kubeconfig, también se redactan; con `--output text`, se redactan la salida propia de la instalación y su error. Un kubeconfig que no puede leerse o con el que no puede crearse un cliente se informa por el tipo de problema, el archivo y el nombre del contexto. Un valor demasiado corto para redactarse (menos de 4 bytes) se advierte en lugar de dejarse sin más. La [referencia del flujo de eventos de la instalación](../reference/install-events.md) enumera ahora todos los campos de cada evento y describe cómo se agrupa el progreso y cuándo una orden de OpenTofu interrumpida puede sobrevivir a la ejecución.

## zh-CN

- **`dcctl install --output json` 在边界情况下也保持其保证。** 退出状态始终与事件流的最终结论一致，为 `0` 或 `1`，即使安装所运行的工具被杀死或 dcctl 自身意外失败也是如此，此时事件流同样以总结行结束；文本输出也重新只以 `0` 或 `1` 退出。`--help` 与 `--output json` 一起使用时，帮助打印在 stderr 上，stdout 保持为空。安装所运行的任何东西都无法读取 stdin，因此 kubeconfig 的 exec 凭据插件以非交互方式运行。dcctl 无法解析的 kubeconfig 现在只按其路径报告，不再附带解析器给出的原因（该原因可能引用文件中的令牌和密码），两种输出格式都是如此；kubeconfig 中的凭据也会从事件流的日志行中移除。使用 `--output json` 时，打印在 stderr 上的错误以及运行期间到达 dcctl 自身 stdout 和 stderr 的其他所有内容（包括 kubeconfig 的 exec 凭据插件的 stderr）也会被替换；使用 `--output text` 时，安装自身的输出及其错误会被替换。无法读取或无法构建客户端的 kubeconfig 按问题类型、文件和上下文名称报告。过短而无法替换的值（不足 4 字节）会给出警告，而不是被默默放过。[安装事件流参考](../reference/install-events.md)现在列出每个事件的全部字段，并说明进度如何合并，以及被中断的 OpenTofu 命令何时可能比运行存在得更久。
